### ⚠ 自动化本身的踩坑（已实测，记录以免重犯）

1. **`automation_update` 没有 delete 模式**（只有 view / suggested create / suggested update）
   ⇒ 「取消」= `status=PAUSED` + **`validUntil` 设为过去日期**（= 已过期 ⇒ 永不执行），并把 name/prompt 改成「已取消」+写明原因。
2. **改 `scheduleType` 不生效**：`once` 的自动化改成 `recurring` 会**静默保留原 `once`**
   ⇒ 要换调度类型只能**新建 + 取消旧的**。
3. **`id` 由 name 派生（会随改名而变）** ⇒ 改名后用旧 id 会 `Automation not found`。
4. **多值 `BYMINUTE` 会被错误展开**：`FREQ=WEEKLY;...;BYHOUR=<24个值>;BYMINUTE=0,20,40`
   实测 `nextRunAt` 落到 **5 小时后（00:20）而不是 20 分钟后**（旧 `loop-gen50` 同症状：落到 00:00）
   ⇒ **只用文档里明确支持的最简形式**：`FREQ=HOURLY;INTERVAL=1`（实测 `nextRunAt` 正好 +1 小时 ✓）。
5. **存储位置**：`C:\Users\Administrator\AppData\Roaming\CodeBuddy CN\automations\automations.db`（SQLite，带 -wal/-shm）
   ⇒ **不要手动改它**（IDE 在用，并发写有损坏风险）。

**当前自动化清单**：`automation`（轮询者，ACTIVE） / `loop-gen50`（**已取消**：PAUSED + 已过期）。
