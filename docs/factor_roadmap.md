### 5. 对提案的修订（下方 §3/§4 同步生效）

1. **★ P1 设计修订（2026-09-11 晚，据批1 标定）——"novelty 进 score"改为「硬性反冗余闸门」**。
   - **原设计**：`score = |IC_IR| × shape × novelty`（novelty 与 IC_IR 同量级相乘）。
   - **标定实测反驳**：`novelty` 与 L2 Calmar **负相关（−0.42~−0.52）**，乘法加权后排序分相关性
     **从 +0.493 崩到 −0.119**（详见 §8）。且 `maxcorr_bank` 与 L2 结果**正相关 +0.52**。
   - **根因（我混淆了两个目标）**：novelty 的目标是**反冗余 / 结构多样性**，
     **不是"提高 L2 通过率"**。用"与 L2 结果的相关性"去衡量它是错的口径。
   - **修订后设计**：novelty **不参与排序分**，改为**独立的硬性闸门**：
     `若 max|corr(候选, bank)| > thr_dup（初值 0.90）→ 直接拒`；
     其效果用**库内独立因子数 / 结构族多样性 / 叶子分布熵**衡量，**不用 L2 通过率衡量**。
   - **仍需保留的事实**：F25/F28/F29/F30 与旧库相关 **0.54~0.63** 全部通过 `decorr`（阈值过松）→
     反冗余闸门确实有必要，只是它的收益体现在"库的结构质量"，不在"单代通过率"。
   - ⚠ **方法论污染待解**：标定里 `novelty` 是用**最终 bank（30 个）**去度量**历史候选**的
     （gen20 的候选从未与 gen70 的因子比过）；archive 未记录"当时 bank"，只能近似。
2. **P0（形状门槛）证据增强**：F25~F30 十档单调性 0.96~1.00 且最优档全为 D1 → 加单调性门槛
   **不会误杀这批**，而能拦下历史上出现过 D2>D1 的（如 F17 型极端档污染）。
3. **★ 新增维度：频率口径需要重审（提案原先没有），但它与成本档强耦合**。

   CLI `--min_mono`，**默认 0 = 关闭**（可回退）。
2. **排序分改写（P0，比加门槛收益更大）**：
   `score = stab × (0.5 + 0.5 × shape_pos)`，**去掉 `|ic_ir|` 的乘法**。
   - 依据：`ic_ir` 与 L2 结果 **负相关（−0.317）**，把它乘进去是在**稀释 `stab` 的正信号**
     （`stab` 单独 +0.546 → 现状组合只有 +0.167）。
   - **IC 仍保留为门槛**（`ic > min_ic`），只是不再当排序驱动——与既有结论
     "**IC 排序 ≠ 分组超额，不能用 IC 挑因子**"一致。
   - CLI `--score_mode={old,new}`，**默认 old**（可回退）。
3. **novelty 改硬性反冗余闸门**（不做排序项，见 §5-1）：`--max_corr_bank`（vs bank 的
   `|corr|` 上限），默认 0 = 关闭。
4. ⚠ **两条必须记住的局限**：
   - 标定样本是**已过 L1 的候选**（截断样本）→ 只能用于选"**大幅优于现状的简单公式**"，
     不可精细调参；最终须**真实跑 3~5 代**验证（通过率、结构性指标）。
   - `novelty` 用的是**最终 bank** 度量**历史候选**（污染）；且它负相关是"用 L2 通过率衡量
     反冗余"的**口径错配**，不代表反冗余闸门没有价值。

### 8.3 ⚠ 跑批1 前的风险备忘（2026-09-11，代码核实所得）

> 批1 的开关已实现但**从未真实运行**（`loop_journal.md` 最后一代 = gen70 = **改造前代数**）。
> 也就是说：**到 2026-09-11 为止，本日改动的引擎行为影响 = 0**（`--min_mono=0` / `--score_mode=old`
> 逐位等于改造前）。开跑 3~5 代验证前，先记录两条**由代码结构推出、标定本身看不出来**的风险。

**风险① `--score_mode=new` 可能在「低换手 / 低成交额」方向上加倍下注 —— 与改造目标反向**

> ⚠ **本条已于 §8.5 实测否定（方向相反）**：`new` 反而**降低**了低换手暴露；
> 但实测发现它**放大市值暴露 1.7 倍** —— 风险换了方向。下面的推理链保留作记录，
> **结论请以 §8.5 为准**。

三条独立事实叠加（任一条都不足以定论，合起来指向同一结论）：

1. 新排序分 = `stab × (0.5 + 0.5·shape_pos)`，而 `stab` 在本引擎里**就是低换手代理**——
   代码原话 `turn_est = 1 - stab`（`loop_engine.py` L1 排序处）。
2. 批1 标定显示 `stab` 与 L2 Calmar **最强正相关（+0.546）**（§8③）→ 引擎会更偏好高 `stab`。
3. 对外分析（F25~F30）的结论：这批因子的**主战场 = 低换手 + 低成交额暴露**
   （F25 `lntr −0.393`、F30 `lnamt −0.389`），**市值暴露反而已明显减轻**。

⇒ **新排序分被设计成"更偏好低换手"，而当前因子的主要风格问题恰恰是"低换手/低成交额扎堆"。**

这不是标定的缺陷（标定衡量"能否盈利"，不衡量"风格是否更集中"），而是**目标函数没覆盖的维度**。
**若验证时只看通过率 / Calmar，会把"风格加倍下注"误读成"改造成功"。**

**风险② `--decorr` 是"对两个固定函数形式查相关"，不是风格暴露控制**

`--decorr` 的对比对象只有两项 + bank：

```python
KNOWN = {'ln_mktcap': log(mktcap), 'amt_log': -log(ts_mean(turnover, 20) + 1)}
```

- 只覆盖**两个特定函数形式**。换个非线性成交额变换（如 `ts_delta120(cs_rank(turnover))`），
  与这两项的 corr 可以很低，**但风格暴露一样重**。
- 它是**防"重复发现旧因子"**的闸门，**不是"控制风格暴露"**的闸门 —— 两者常被混为一谈。
- 真正的风格暴露控制应看「**对风格回归后的残差**」，这也正是批2 已列项的
  「剥风格后超额作门槛」要解决的问题（两条是同一件事）。

### 8.5 ★ 实测结论：批1 排序分**不加重低换手**，但**放大市值暴露 1.7 倍**（2026-09-11）

> 方法：`--style_obs` **单臂** + 离线配对（见 §8.4）。样本 = **2125 个候选 / gen71~73**，
> 门槛与引擎 L1 同口径（`ic>0.02` + `stab>=0.75`，**三代均从日志核对一致**）。
> 报告全文 `docs/loop_style_paired.md`；脚本 **`standard/style_paired_analysis.py`**（可复跑复核）。

**Top-30 池化（每代取前 30、三组合并 90 个）**

| 排序分 | \|lncap\| | \|lnamt\| | \|lntr\| | \|lnpx\| | 中位 lncap | 中位 lntr |
|---|---|---|---|---|---|---|
| **全池基准**（过门槛 1156 个） | 0.121 | 0.295 | 0.344 | 0.088 | **−0.040** | −0.344 |
| `old` = `\|IC_IR\|×(0.25+0.75·stab)` | 0.158 | 0.312 | 0.225 | 0.071 | −0.158 | −0.225 |
| `new` = `stab×(0.5+0.5·shape_pos)` | **0.272** | 0.359 | **0.157** | 0.103 | **−0.272** | −0.134 |

**各代 Delta（new − old）**：`lncap` **+0.099**（+0.109/+0.137/+0.051，**三代同向**）、
`lntr` **−0.109**（−0.175/−0.098/−0.054，**三代同向**）、`lnamt` +0.042（**符号不一致，不稳健**）、
`lnpx` +0.033（同向）。`old∩new` 重叠率仅 **20~27%**（Top-70 为 46~52%）→ 改选是**结构性**的。

**三条结论**

1. ❌ **§8.3 风险① 不成立（方向相反）**：新排序分**降低**了低换手暴露
   （`|lntr|` 0.225→0.157；中位 −0.225→−0.134，三代同向）。
   原推理"`stab` 是低换手代理 ⇒ 新公式加重低换手"**漏掉了 `old` 里的 `|IC_IR|` 本身就在挑低换手**
   —— 这与标定里"`ic_ir` vs L2 Calmar **−0.317**"同源：**高 IC_IR 往往伴随低换手暴露**。
   **这是本次观测最有价值的产出：推翻了一个看似合理、且已写进 §8.3 的假设。**
2. ⚠ **但市值暴露被放大 1.7 倍，且是选择压力新引入的**：候选池本身**接近市值中性**
   （中位 `lncap` −0.040），`old` 已带 −0.158 的小市值倾向，`new` 加倍到 **−0.272**。
   ⇒ 对「别老在市值/成交额打转」这个目标，**问题没消失，只是从"低换手"换成了"小市值"** ——
   而小市值恰是历史 T4 因子被判"需谨慎"的主因（F24 `lncap −0.424`、F14 `−0.355`）。
3. ➖ 成交额暴露方向不稳（+0.051 / +0.077 / −0.003），**不宜下结论**。

**⇒ 对批1 的行动含义**

- **不要把 `--score_mode` 的默认值直接翻成 `new`**。标定说它与 L2 Calmar 相关性更强
  （+0.668 vs +0.167），但那是**截断样本**上、且**目标函数里没有风格暴露这一维**。
- 两者真正的分歧是：**宁可要"能赚钱但小市值扎堆"，还是"平庸但风格中性"** ——
  这是**目标函数缺一个维度**，不是换个排序公式能解决的 ⇒ 正是批2 已列项的
  「**剥风格后超额作门槛**」（`standard_test.py` 已有 `neutralize()` 可复用）。
- **若仍想用 `new`，建议先做这一步**（改动小、可直接用本脚本复核）：
  把 `decile_shape` 的收益入参 `R` 换成**剥掉 `lncap`/`lnamt` 之后的截面残差收益**
  → `shape_pos` 就从"原始档位单调性"变成"**风格中性后的档位单调性**"，
  排序分便不再奖励小市值暴露。改完重跑本测量（同命令）即可对比。

## 2026-09-11（一）：挖掘架构重构提案（十档分层 / 多池 / 去单一 IC 排序）

> **状态：提案（本节未改任何代码）**。触发原因：gen40~50 复盘显示"L1 按 IC 排序、L2 费后全灭"
> （9 代仅 2 代入库、L2 多为 0/30），且**形状（十档）、池（300/500）、新颖性**三个维度
> 完全没进入选择压力。落地后逐项回填「已实现 / 验收结果」。

### 1. 现状选择链（2026-09-11 逐环核实 `engine/loop_engine.py`）

| 层 | 做法 | 判据 / 排序 |
|---|---|---|
| **L0 生成** | 守卫链：跨量纲 / FSA 骨架冻结 / 失败库 / 族配额 | 800 候选·代 |
| **L1 粗筛** | 子面板 2094 日 × 2000 股，批量向量化 IC（比逐个 evaluate 快 30x） | 门槛 `ic>min_ic` 且 `stab>min_stab`；`decorr` 对 bank + 2 个基准；**排序分 `score = \|IC_IR\| × (0.25 + 0.75·stab)`**；取 Top70 → 近重复去重(`dedup_corr`=0.85) → 族配额(≤2) |
| **L2 精筛** | 全面板 `evaluate_real`：往返 0.5% 费后 + 涨停不可买 + 跌停顺延 | `factor_miner.pass_filter` 11 项 + `calmar>min_calmar` + `sharpe>0.5` + `seg_verify` 分段 |
| **L3 入库** | 与 bank 去重后 append | — |

池：**全 A 单池**（`loop_engine.py` 内无任何 `000300/000905/成分股` 引用）；FWD = 5。

### 2. 四个结构性缺口

1. **两级目标不同轴**：L1 排序只含 `预测力 × 稳定性`；L2 判据是 `Calmar / 费后超额 / 11 项`。
   L1 的 Top70 里大量候选在 L2 因 Calmar 不足全灭 → **最贵的一层在替最便宜的一层做筛选**。
2. **三个维度缺席选择压力**：形状（十档单调性 / 最优档 / D1 污染）只在**入库后** `standard_test`
   才看；池（300/500）只活在**评估侧**（`standard_test.py` / `audit_f11.py`）；成本仅有 `stab` 的隐式换手代理。
3. **新颖性是硬门槛而非计分项**：`decorr` 是"超了就丢"的开关 → L1 Top70 仍是"IC 最高的 70 个"，
   同质化严重（叶子垄断 `barra_residual_volatility` 100%，gen47 起）。
4. **反垄断全是"事后数量上限"**：`fam_quota` / `dedup_corr` / `decorr` 只做"超了就丢"，
   无结构距离衰减、无叶子配额。

### 3. 提案：同轴漏斗（L1 改用接近 L2 的目标口径 + 便宜子集）

**关键取舍**：L2 `evaluate_real` 是逐因子全面板回测，**无法与 L1 合并**（L1 靠批量向量化才快 30x）。
所以只能"**用廉价代理逼近最终目标**"，而不是两级各用一套互不相干的指标。

**(1) 统一指标层 `engine/loop_metrics.py`**
一个参数化函数 `metrics(v, freq, pool, cost, segment, n_grp) -> dict`，统一输出五族：
预测力（IC / IC_IR / IC 胜率）、形状（十档超额向量 / 单调性 / 最优档 / D1 是否污染）、
可实现性（费后超额 / Calmar / Sharpe / 换手）、稳健性（分段 / 逐年 / 多池）、新颖性（vs bank 的 max\|corr\|）。
L1 调"子面板 + freq=5 + 全A + 十档"的廉价子集，L2 调完整集 —— **同一份代码，不同参数**。
> 副产物：这份 dict 既是因子记录的 `metrics` 字段，也是 qlib_code 看板的指标契约
> （见 `docs/software_framework.md` §3）→ **一次定义，三处复用**。

**(2) L1 改「三道门槛 + 三维排序分」**
- 门槛① 预测力：`|IC_IR| > thr_ic`（沿用）
- 门槛② **形状**：十档单调性 Spearman > `thr_shape`（新增；复用 `decile_stats` 逻辑，子面板向量化）
- 门槛③ 可实现性：换手代理 < `thr_turn`（把现有 `stab` 显式化为门槛）
- 排序：`score = |IC_IR|^a × shape^b × novelty^c`
  - `shape` = 单调性 × (最优档 == D1 ? 1.0 : 0.5)　← 顶档污染降权
  - `novelty` = 1 − max\|corr(候选, bank)\|　← **治叶子垄断的关键**
- 成本：十档在子面板上 = rank + 分组聚合，向量化后增量约 +30~50%
  （远低于"L2 全灭再重来"的白跑成本）
- ⚠ **标定要求**：当前通过率本就极低（9 代仅 2 代有入库），形状门槛必须先用**宽松阈值跑 3~5 代标定**，
  不可一次卡死。标定口径 = 回放 gen40~50 的 L1 日志，统计"被 L2 判死的候选有多少会在 L1 被形状门槛拦住"。

**(3) 多池：定位决定用法（别当成第二个收益指标）**
- 300/500 内仅 300/500 只股票 → 池内多头组合噪声大 → **不要用"池内收益"做选择**。
- 正确用法：**池内一致性作验证门槛**（"全 A 上成立 + 300/500 内同向"）或作稳健性加分。
- **前提：必须 PIT 逐日历史成分**。用当前成分回测过去 = 幸存者偏差（"后来才被纳入"的股票会被当成
  历史成分）。需先确认 `E:\rq\constituents\index\000300.XSHG.h5` 是逐日快照还是静态名单。
  **这一步未验证前不要开工。**
- 推荐组合：**全 A 选择（样本大、稳）+ 300/500 验证**；反向（小池选择、全 A 验证）会让选择过拟合小样本。

**(4) 反垄断：事后拦 → 事前计分 + 双层配额**
- `novelty` 进 score（见 (2)）
- **`leaf_quota`**：同代 L1 通过集中任一叶子的出现次数上限（治 `barra_residual_volatility` 100%）
- **结构距离衰减**：同一 `root_fam` 第 k 次出现 → `score × decay^k`（比硬上限平滑，避免"第 3 名整族被砍"）

**(5) 成本敏感度**
